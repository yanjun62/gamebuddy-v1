# Source and release policy

## Evidence ledger

For each precise claim, keep a short source note with:

- claim and game edition or patch;
- source URL or a clear local reference the player may inspect;
- evidence level: primary, reliable secondary, community report, or unverified;
- spoiler level needed to use the claim.

Prefer official manuals, patch notes, in-game journals, developer material, or a well-maintained Wiki that cites the game. Label a community finding as community-sourced. Do not invent an exact check target, cutoff, or outcome because it sounds plausible.

## Terminology and localization

Use names, places, factions, skills, and mission titles as recognition hints. Prefer the player's on-screen localization when it differs. Do not include full subtitle or dialogue text merely to improve recognition.

Keep a large glossary optional. Include only compact, high-value terms in the default speech prompt. Add scope and confidence when a translation differs by game, patch, or localization mod.

## Public-release checklist

- Separate project code and self-authored guide prose from third-party data.
- Preserve attribution and any non-commercial, credit, or no-derivatives conditions attached to source material.
- Exclude raw game assets, localized strings, subtitle corpora, screenshots, maps, save files, user exports, credentials, and machine-local paths unless the rights holder has clearly allowed redistribution.
- Do not relicense third-party terms or trademarks under the project’s software license.
- Include a concise notice describing excluded datasets and how a user can create an optional local dataset from material they are entitled to use.
